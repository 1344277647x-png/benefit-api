# 文本流失败后的计费

## 行为

此前 controller 的错误收尾无条件退款，部分文本适配器在错误时丢弃 usage，因此已经生成或交付的输出可能得到全额退款。这是源码确认的风险路径；本轮没有主动在生产触发漏洞。

本次修复为 Responses、Chat Completions、Responses 转 Chat、Claude 和 Gemini 文本流保留部分用量：

- 优先使用收到的上游 usage，保留缓存等计费明细。
- 缺失输出计数时，对已经收到的文本或 Responses 函数参数增量估算 Token。输入计数缺失时使用本请求已有估算。估算并不包含未收到的隐藏推理或未来输出。
- 只有心跳或空生命周期事件时不建立收费证据。失败状态和错误处理保留，不伪造成功完成事件。
- 有生成用量的失败请求不再跨渠道重试；正常成功请求仍走原有结算。
- 错误收尾按原计价规则结算部分用量，不再对该请求执行全额退款。同一请求上下文重复执行不会重复记账。
- 结算失败不转为全额退款，保留预扣，输出带请求上下文的管理员告警，不写成功消费日志或增加成功消费计数。
- 消费日志管理员字段 `admin_info.partial_stream_billing` 标记 `usage_source` 和 `request_succeeded=false`。普通用户仍可看到实际消费，但管理员标记按已有日志权限过滤。

## 验证范围

隔离 Go 测试覆盖：Responses 输出后 EOF、完成事件写入期间取消、函数参数中断、空心跳、Chat 上游 usage 后错误及缺少 DONE、Claude 输出后错误、Gemini 文本 EOF 和无 usage 图片、钱包与令牌一次扣费、订阅不扣钱包、结算故障保留预扣且不生成消费日志。测试不请求付费上游。

## 限制与发布

音频按用户要求排除。没有可信 usage 的媒体不能用文本估算价格；独立创作图片账务保持原路径，本次不宣称所有媒体协议已修复。Claude 原有正常 EOF 成功处理未在本轮重新定义，只将异常 scanner/客户端等终态保留为失败。

幂等保护为本请求上下文和已有 BillingSession，不是跨进程持久资金账本。结算失败暂无自动持久重试/对账队列，需人工依据请求号核对；进程崩溃后的资金恢复及审计报告中的其他资金原子性问题属于后续批次。保留预扣可能暂时多于已观察到的消耗，不能把告警当作最终已结算。

本轮只完成本地修改与隔离验证，未推送或部署计费补丁。上线须单独授权，并完成镜像构建、数据库/Compose 备份和实际日志验收。回滚该代码时不会自动冲正已按部分用量结算的历史记录。

## 第二批补充（2026-10-09）

腾讯和 Coze 文本流以及 Chat 转 Responses 现在也在错误返回时保留已收用量。腾讯优先真实 usage；Coze 下游写入错误不再忽略。OpenAI 图片 SSE 仅在有可信上游 usage 时保留该用量，图片二进制不会作为文本估算。无 usage 的图片/部分图片仍未具备可靠的失败计价与持久待对账流程，不能据此宣称媒体漏洞全部关闭。

补充测试覆盖腾讯真实/估算用量、Coze 截断、Chat 转 Responses 截断和图片 SSE 已收到 usage 后缺少完成事件。十一个相关 Go 包全回归通过。
